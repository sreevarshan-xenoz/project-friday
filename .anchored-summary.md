- Build FRIDAY as an Adaptive Cognitive Operating System. **Core 1.0 frozen** (Phase A complete: 15+ cognitive modules extracted, 199 tests). **Phase B active**: Plugin Platform — Runtime (Sprint 1: ✅), Capability Catalog & Resolver (Sprint 2: ✅), **Adaptive Selection (Sprint 3: 🚧)**.

## Important Details
- **Core 1.0 is frozen** — zero modifications allowed. All new work goes into `services/plugin-runtime/` or other platform crates.
- **Phase A refactor complete**: ~6600-line `lib.rs` → ~2200 lines, 16 cohesive modules, public API preserved via re-exports. 199 tests pass, clippy clean.
- **Sprint 1 deliverable**: Plugin Runtime proves the extension pipeline. `CapabilityRequest → Resolver → Runtime → FilesystemPlugin → CapabilityResult → HealthMonitor`. 34 tests pass.
- **Sprint 2 deliverable**: `CapabilityCatalog` (semantic descriptors), `CapabilityPlanner` (multi-factor scoring, `PlanningRationale`), `PolicyEngine` trait + `RuleBasedPolicyEngine`, wired through runtime. 51 tests (41 unit + 10 integration), clippy clean.
- **Sprint 2 architectural achievement**: Five-layer separation — Catalog (what is ReadFile?) → Registry (who implements it?) → Policy (who is allowed?) → Resolver (who should?) → Runtime (execute it). Five different questions, five different components.
- **Sprint 3 (Adaptive Selection)**: Replace the current scoring formula with a system that combines health + policy + experience + confidence. Introduce `SelectionContext` (urgency, budget, offline, security level, user prefs). Split monolithic policy into composable layers (Security/Organizational/Resource/User). Add `ProviderProfile` to separate intrinsic characteristics from runtime health.
- **Roadmap reordered**: B.3 Telemetry Pipeline → B.4 Adaptive Selection → B.5 Dashboard. Reason: can't tune adaptive selection without observing it. Telemetry captures provider chosen, score breakdown, latency, failures, policy decisions, health changes.
- **New milestone added**: Capability Validation — every plugin validated against catalog before registration (required capabilities, version compat, schema conformance, permission declarations) before dynamic loading.
- **Core invariants still active**: Knowledge derived from episodes, blackboard-only engine communication, AttentionManager schedules cognition, Executive orchestrates 10-phase cycle.
- **Phase B roadmap**: B.1 Runtime Foundation ✅, B.2 Catalog & Resolver ✅, B.3 Telemetry Pipeline 🚧, B.4 Adaptive Selection, B.5 Dashboard, B.6 Capability Validation, B.7 Multi-Provider, B.8 Dynamic Loading & SDK.
