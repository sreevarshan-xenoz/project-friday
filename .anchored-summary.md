## Important Details
- **Core 1.0 is frozen** — zero modifications allowed. All new work goes into `services/plugin-runtime/` or `services/experience/`.
- **Sprint 5 (Experience & Reputation)** phases A–H complete: (5A) Core types for ExecutionPlan/PlanOutcome/DecisionRecord/Experience/Reputation. (5B) CapabilityResolver→CapabilityPlanner, plan()/execute() separation. (5C) DecisionLedger — append-only journal. (5D) ExperienceEngine (cursor-based incremental aggregation). (5E) ReputationEngine (derives trust from experience). (5F) CostModel (prediction layer — estimate/rank). (5G) PlannerFeedback::compare() (measure prediction error). (5H) CalibrationStore (bounded learning) + fallback chain traversal (runtime executes pre-made fallback plans).
- **Architecture**: CapabilityRequest → CapabilityPlanner → CostModel → ExecutionPlan → PluginRuntime → PlanOutcome → DecisionLedger → ExperienceEngine → ExperienceStore → ReputationEngine → ReputationStore → CostModel. CalibrationStore and PlannerFeedback close the loop. Invariants: Only planner creates plans; runtime never modifies a plan; runtime never generates plans (only executes existing fallback chains); every execution produces a DecisionRecord; DecisionRecord processed by ExperienceEngine at most once; Experience derived from DecisionRecords; Reputation is a projection of Experience, never of DecisionRecords; CostModel may change estimates but never rewrites history.
- **Pipeline complete**: Prediction is its own layer, distinct from aggregation (Experience), trust (Reputation), and learning (Calibration). Four information layers: Runtime (reality), DecisionLedger (history), ExperienceStore (knowledge), ReputationStore (trust).

- **Sprint 5E**: ReputationEngine + ReputationStore. Derives trust from Experience. Four fields: reliability, confidence, total_observations, last_updated. Decay factor constant 0.95.
- **Sprint 5F**: CostModel. `estimate()` blends Experience (sample-weighted) + Reputation (confidence-weighted). `rank()` sorts by success probability. `apply_feedback()`/`invalidate()` as placeholders.

(2) Fallback chain traversal in PluginRuntime.resolve_with_fallback() — runtime iterates pre-made plans, never generates new ones. 6 fallback tests (primary success, no chain, chain succeeds, chain fails, early exit on success, failed-attempt recording).
