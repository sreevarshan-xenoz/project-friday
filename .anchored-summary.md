## Important Details
- **Core 1.0 is frozen** — zero modifications allowed. All new work goes into `services/plugin-runtime/` or `services/experience/`.
- **Closed-loop architecture validated**: CapabilityRequest → CapabilityPlanner → CostModel → ExecutionPlan → PluginRuntime → PlanOutcome → DecisionLedger → ExperienceEngine → ExperienceStore → ReputationEngine → ReputationStore → PlannerFeedback → CalibrationStore → Future Cost Estimates. No backward dependencies through all seven phases.
- **Top invariant**: **"History is immutable. Intelligence is derived."** — DecisionRecord never changes; Experience is a deterministic projection of the ledger; Reputation is a deterministic projection of experience; Calibration influences only future estimates; predictions evolve, observations do not.
- **Two orthogonal pipelines**: Operational (Plan → Predict → Execute → Record → Learn → Calibrate) and Observability (Execution Artifacts → ExplanationEngine → DecisionExplanation → DecisionTimeline → Metrics (6C) → Replay (6D)). They never interfere.
- **CostModel signature (current)**: `estimate(capability, operator_id, experience_store, reputation_store, calibration: Option<&CalibrationStore>)`. `rank()` accepts same `calibration` param. `apply_feedback(&PlannerFeedback, &mut CalibrationStore)` implemented. `invalidate()` remains `todo!("Phase 5H: invalidation")`.
- **Calibration design**: `CalibrationStore` + `CalibrationOffsets` (+ `is_zero()`). Learning rate 0.3. Per-step clamps (latency ±100ms, cost ±0.5), global clamps (latency ±500ms, cost ±1.0, success ±0.3, confidence ±0.5). HashMap<ExperienceKey, CalibrationOffsets>.
- **Fallback traversal invariant**: Runtime only executes pre-existing plans from the immutable `fallback_chain` — it never generates plans. `PluginRuntime::resolve_with_fallback()` (pub(crate)) executes flat chain, records failed attempts in ledger, breaks on first success.
- **PlannerFeedback::compare()** (contract.rs): pure comparison `fn(&ExecutionPlan, &PlanOutcome) -> PlannerFeedback`. Confidence (±): +0.1 correct, −0.3 surprise failure (confidence > 0.7), −0.1 otherwise. Trigger: wrong prediction OR latency error > 50% of estimated OR cost error > 1.0. 13 unit tests.
- **ExplanationReason** (Sprint 6A future-proofing): structured machine-readable enum — HighestCompositeScore, PolicyConstraint, HigherReliability, BetterHistoricalLatency, CalibrationAdjustment, FallbackSelection. Narrative is a rendering of reasons; never parse free text.
- **MetricsEngine (6C) is stateless**: derives PredictionAccuracy, CalibrationMetrics (with first-half/second-half convergence signal), FallbackMetrics, ReputationMetrics, ExperienceMetrics from `&[DecisionTimeline]`. `summarize()` → MetricsReport. Empty input → all-zero metrics. Metrics are derived, never stored.
- **ReplayEngine (6D) builds on read models**: `replay(&DecisionTimeline, &ExperienceStore, &ReputationStore, &CalibrationStore) -> ReplayReport`. Comparison between two evaluations, never a history rewrite. Structured as immutable `historical` (plan, prediction, explanation, outcome), current `replay` (plan, prediction, explanation, ranked_candidates), and `differences` (operator_changed, `decision_still_optimal` = !operator_changed regression signal, PredictionDelta, reputation_delta Option, calibration_delta Option, explanation_delta added/removed ExplanationReasons via ExplanationEngine), plus replay_timestamp_ms. Owns no state.
- **Read-model naming convention**: `*Engine` = computes derived values (`ExperienceEngine`, `ReputationEngine`, `ExplanationEngine`, `MetricsEngine`, `ReplayEngine`); `*Builder` = assembles a composite snapshot (`TimelineBuilder`). Renamed `Explainer` → `ExplanationEngine` (Sprint 6A) to join the family.
- **Three-layer architecture (documented)**: Execution / Learning / Observability. `docs/DecisionIntelligence.md` §2 has the authoritative three-layer diagram; §9 documents the `friday-experience` public API (all stores + read-model types are public by design — no internal helpers exposed), with every public type annotated `stable` (Sprint 5 learning core) or `experimental` (Sprint 6 observability).
- **Test counts**: experience crate 49 + plugin-runtime 97 unit + 11 integration + goal-execution 199 (187 unit + 12 integration) = **356 tests, all passing. Clippy clean on friday-experience.**
