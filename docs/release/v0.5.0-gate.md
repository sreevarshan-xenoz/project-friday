## Found on the way

- OpenCode Zen refuses keyless API calls from FRIDAY with
  `FreeUsageLimitError` ("Free models work in OpenCode"). FRIDAY now also
  asks through OpenCode's own CLI when it is installed (`opencode run
  --standalone`, empty config, every tool denied), after the Zen API and
  before Kilo. Checked live: answered "Paris" while the API refused. The CLI
  draws on the same per-machine free quota and ran out after about ten
  requests, so it is headroom, not a cure; Kilo and OVHcloud still back it.
  The lockdown was checked with a fake local model that logs the tools it
  is offered: normally OpenCode offers `edit, shell, write, execute,
  webfetch, websearch, subagent, read, grep, glob` (plan mode too); with
  FRIDAY's settings it offers only `skill`, which has nothing to load. Without
  `--standalone` the run goes through the person's background service and
  the settings are ignored. Open decision: whether Kilo goes first.
- Locally, `run-checks.sh` fails the Dots-Hyprland and window-look checks
  against the host's own Hyprland and Quickshell; CI passes them on the same
  commit.
