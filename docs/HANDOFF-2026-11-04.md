## Follow-up (same day, later session)

- **Installer pacstrap now retries** (`5e9193e`): up to `PACSTRAP_ATTEMPTS`
  (default 3) with 10s/20s back-off, so a single mirror timeout no longer
  kills the install.
- **Broadcom driver dropped** (`2f4bbe3`). `c7ddd4c` first swapped in the
  prebuilt `broadcom-wl`, but a real build showed that package no longer
  exists ("target not found"). Only `broadcom-wl-dkms` remains and it never
  built without `linux-headers`; archiso's current `releng` ships no
  Broadcom driver, so it and its `modprobe.d` override are gone.
- **SDDM theme root cause.** Loaded `silent-friday/Main.qml` headlessly
  (PySide6 / Qt 6.12, stubbed `sddm`/`config`/models, theme components on
  the import path as `10-theme.conf` sets them). With every Qt module present
  it loads and renders. With `QtQuick.VirtualKeyboard` removed it reproduces
  the Sep 13 screenshot exactly, including the line cut off at the bottom:
  `Main.qml:239:13 LoginScreen unavailable` →
  `LoginScreen.qml:448:5 MenuArea unavailable` →
  `MenuArea.qml:4:1: module "QtQuick.VirtualKeyboard.Settings" is not installed`.
  The broken screenshot was taken at 14:22 on Sep 13. `qt6-virtualkeyboard`
  (with the other `qt6-*` theme deps) was added to the installer's pacstrap
  list in `c0c21c3` at 20:02 the same day, so the theme should load on a
  fresh install. Confirm on the next `--boot disk` run.

  100644. Binaries/installer now stored 100755 (`16e45bc`) and the script
