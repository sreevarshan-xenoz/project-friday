## Live ISO in QEMU — PASS

`run-qemu.sh --headless --daemon --reset-disk`, UEFI boot:

- Boots to the FRIDAY TUI configurator on tty1 (`friday-installer.service`);
  it detects `/dev/vda` (25G) and excludes the boot media.
- `/usr/bin/{friday,friday-ctl,friday-linux-daemon,friday-skill-forge}` present.
- `friday-linux-daemon` running.
- `systemctl is-system-running` = `degraded`; only failed unit is
  `systemd-loop@…block-sr0.service` (attaching the CD-ROM to a loop device).
  Probably cosmetic, but it keeps the live system "degraded".
- No desktop on the live ISO by design — SDDM/Hyprland only on the installed
  system.

Gotcha: `vm-control.py wait-ready` reports "SSH online after 0s" immediately,
because QEMU's port forward accepts TCP before the guest is up. Poll a real
`ssh … uptime` instead.
